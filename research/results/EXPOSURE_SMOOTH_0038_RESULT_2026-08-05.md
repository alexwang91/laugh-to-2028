**这个实验只改了一件事**：把 `btc_last_drop_beta` 里"趋势 ≥ 0 走一条公式、趋势 < 0 走另一条公式"的两段式仓位函数，换成一条连续直线：

```
原始值 = (0.65 + 0.65 × 趋势) × 波动乘数
仓位   = 裁剪到 [0.18, 1.30]
```

四个常数（0.65 斜率、0.18 下限、1.30 上限、波动分档乘数）**全部沿用旧公式里已有的值，没有引入任何新参数**。选币逻辑、每个币的仓位上限、趋势分数怎么算、波动率怎么算——全部原样不动。alt 币"趋势转负就清仓"这个硬开关也没碰，留给下一次单独测试。

单元测试（6 项，全过）验证了：新公式在 t=1 低波动时精确等于旧公式的上限 1.30，在 t=0 精确等于旧公式的下限值，跳变随区间收窄成比例缩小（不是固定跳变），且波动率现在能在强上涨趋势下也降低仓位。

## 这个结果意味着什么，以及不意味着什么

**意味着**：这三个从代码结构诊断出来的缺陷（0 点跳变、波动响应死区）是真实的，修复它们在全历史面板上不是负和游戏——最坏情况（2021年5月、全历史最大回撤）明显改善，夏普和卡玛在全历史口径下也提升了。

**不意味着**：

1. **这不能直接替换 README 里的 V1 基线。** 现有的 V1/BRRK-0011 数字、以及所有下游依赖它们的实验（离散度调节、ASYM-BETA 系列），都是建立在旧公式上的。换公式意味着这些数字全部要重新算，这是一次更大的决策，不在本次实验授权范围内。
2. **alt 币仓位切换的硬阈值缺陷没有修。** 5月崩盘期间趋势穿越 0 的次数（10 次）新旧版本完全一样——因为这次没碰这个开关。换手能降到 38%，说明大部分伤害确实来自仓位大小的跳变，但这个开关本身仍然是一个待办项。
3. **3.65 年 / 5.25 年的样本量，仍然不足以统计确证任何差异**（夏普差的置信区间包含 0）。
